This page covers what changes once Riven is more than a test install. For the
initial setup, see [Getting Started](/docs/getting-started).

## Requirements

- Linux host with FUSE support
- Docker Engine 24+ with Compose V2
- PostgreSQL 17 and Redis 8

## Media Server Integration

Add your media server to the same compose file. Riven's container uses
`rshared` propagation to publish its FUSE mount; consumers use `rslave` to
receive it:

```yaml title="Jellyfin example"
jellyfin:
  image: jellyfin/jellyfin:latest
  ports:
    - 8096:8096
  volumes:
    - jellyfin_config:/config
    - /mnt/riven:/mount:rslave,z
  depends_on:
    riven:
      condition: service_started
```

<Callout type="warn">
  The media server must start *after* Riven has mounted the VFS. If it scans an
  empty mount it will mark the library as unavailable.
</Callout>

## Reverse Proxy

Point your proxy at port `9000`. That's the frontend, which runs in the same
container as Riven and forwards the GraphQL API (`/graphql`) and the auth API
(`/api/auth`) to it over the container's loopback, so the proxy only needs the
one port.

```yaml title="Traefik"
labels:
  - traefik.enable=true
  - traefik.http.routers.riven.rule=Host(`riven.example.com`)
  - traefik.http.routers.riven.entrypoints=websecure
  - traefik.http.routers.riven.tls=true
  - traefik.http.routers.riven.tls.certresolver=leresolver
  - traefik.http.services.riven.loadbalancer.server.port=9000
```

```nginx title="Nginx"
server {
    server_name riven.example.com;

    location / {
        proxy_pass http://localhost:9000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

The proxy must pass the browser's `Host` header through (Traefik and Caddy do
by default; Nginx needs `proxy_set_header Host $host`). Riven trusts sign-in
requests from the host the browser used, so the public URL doesn't need to be
configured for signing in. Passkeys and Plex sign-in still do - see the
[frontend's reverse proxy notes](/docs/frontend/getting-started#reverse-proxy).

<Callout>
  Riven's own API port (`3000`) only listens inside the container unless
  `RIVEN_SETTING__host` is `0.0.0.0`. Bind it only if other containers, such as
  Seerr, call it directly. There's no need to publish it: port `9000` serves the
  same API.
</Callout>

## Pinning a Version

`:main` tracks the latest build of the default branch and can change under you.
For production, pin a release instead:

```yaml
image: ghcr.io/rivenmedia/riven-ts:1.2.3
```

Available tags are on the
[package page](https://github.com/rivenmedia/riven-ts/pkgs/container/riven-ts).
There is no `latest` tag.

## Updating

```bash
docker compose pull
docker compose up -d
```

Database migrations run automatically on startup.

## Backups

PostgreSQL holds your library — media items, requests, streams, and the VFS
file entries. Back it up:

```bash
docker compose exec postgres pg_dump -U riven riven | gzip > riven-backup.sql.gz
```

Keep your `.env` and the generated ranking config (`./data`) too. Logs are
disposable, and Redis only holds in-flight queue state.
