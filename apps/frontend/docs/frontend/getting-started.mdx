title: Getting Started
description: Open Riven's web frontend from your Docker setup.
---

The frontend is part of Riven's Docker image, so the setup from
[Getting Started](/docs/getting-started) already runs it on port `9000`. Get
Riven running first, then come back here.

The examples assume you'll open the frontend at `http://192.168.1.10:9000`.
Swap in your own host's address, or your domain if you put it behind a
[reverse proxy](#reverse-proxy).

<Steps>
<Step>

### Configure sign-in

Add these to Riven's `.env`:

```bash title=".env"
# Creates an admin account on first boot, as username:password
RIVEN_SETTING__adminUserCredentials="admin:CHANGEME"

# Signs session cookies. Generate one with: openssl rand -base64 32
RIVEN_FRONTEND_SETTING__authSecret="your-generated-secret"

# Anyone who can reach the login page can sign up whilst this is true
RIVEN_FRONTEND_SETTING__enableEmailPasswordSignup="false"
```

<Callout type="warn">
  If `authSecret` isn't set, Riven generates a random one on every start, which
  signs everyone out each time Riven restarts.
</Callout>

</Step>
<Step>

### Publish the frontend's port

Make sure the `riven` service publishes port `9000`:

```yaml title="docker-compose.yml"
services:
  riven:
    image: ghcr.io/rivenmedia/riven-ts:main
    # ...the rest of the service from Getting Started
    ports:
      - 9000:9000
```

The frontend reaches Riven inside the container, so Riven's own port (`3000`)
doesn't need to be published.

</Step>
<Step>

### Restart Riven

```bash
docker compose up -d riven
docker compose logs -f riven
```

</Step>
<Step>

### Sign in

Open `http://192.168.1.10:9000` and sign in with the username and password
from `RIVEN_SETTING__adminUserCredentials`.

Riven only creates the admin account when no admin exists yet, so changing
the credentials later won't change the password of an existing admin.

</Step>
</Steps>

## Moving from a separate frontend container

The frontend used to ship as its own image, `ghcr.io/rivenmedia/riven-ts-frontend`,
which no longer gets updates. To move over:

1. Remove the `riven-frontend` service, which would otherwise clash with Riven
   on port `9000`.
2. Publish port `9000` on the `riven` service instead, and point your reverse
   proxy at it.
3. Drop `ORIGIN`, `BACKEND_URL` and `BACKEND_API_KEY`. The frontend no longer
   reads them.

## Reverse proxy

To serve the frontend from a domain, point your proxy at port `9000`. It must
pass the browser's `Host` header through, which Traefik and Caddy do by
default.

```nginx title="Nginx"
server {
    server_name riven.example.com;

    location / {
        proxy_pass http://localhost:9000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

The `Upgrade` headers matter: live updates use a WebSocket on `/graphql`,
which the frontend forwards to Riven.

Signing in with a username and password works from any address the proxy
forwards, without configuring the public URL. Passkeys and signing in with
Plex need it, as the browser and Plex are told to return to it. For those, set
`RIVEN_FRONTEND_SETTING__origin` to the public URL, e.g.
`https://riven.example.com`, and see
[Configuration](/docs/frontend/configuration#riven-settings).

## Troubleshooting

**"Invalid origin" errors when signing in or out** - your reverse proxy isn't
passing the browser's `Host` header through. Pass it through, or set
`RIVEN_FRONTEND_SETTING__origin` to the URL in your browser's address bar.
Scheme, host and port all have to match.

**Everyone gets signed out when Riven restarts** - set
`RIVEN_FRONTEND_SETTING__authSecret` to a fixed value.
